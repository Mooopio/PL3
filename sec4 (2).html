🌿 Git & GitHub · PL3 Section 4

Deep Explanation

Big picture: Git is a version control tool on your computer that records every change. GitHub is a website that hosts Git repositories online so teams can collaborate. Analogy: Git = “save game” checkpoints in a video game; GitHub = cloud storage where your whole team shares the same save file.
1. Terms to know (from slides)

A repository (repo) is a storage location where all files of a project are kept, including code and changes made over time.

Git tracks every modification, letting developers revert to previous versions if needed.

In GitHub, the repository is hosted online, so developers collaborate on the same project from different locations.

The slide diagram: Master (green) is the main line. Your work (blue) branches off, makes several commits, and merges back. Someone else’s work (orange) branches and merges back too. Branching lets people work in parallel without breaking the main line.

2. Installing Git on Windows
  1. Google “git download for window” → official site git-scm.com/downloads/win.
  2. Choose 64-bit Git for Windows Setup (standalone installer). Options: 32-bit setup, Portable “thumbdrive” editions, or the winget tool.
winget install --id Git.Git -e --source winget

Slides use version 2.47.0(2), released 2024-10-22. After install, search “Git Bash” in Windows and open it: a black terminal (MINGW64) appears with a $ prompt.

3. Configuring your identity 
git config --global user.name "shereen"
git config --global user.email "shereenyehia@gmail.com"
git config user.name        # prints: shereen

--global = applies to all repos for this user. Name + email are stamped on every commit (Author: in git log). Running git config user.name without a value reads the setting.

5. Local workflow step by step 
git init "myproject"     # Initialized empty Git repository in C:/Users/DELL/myproject/.git/
cd myproject
ls            # shows nothing
ls -a         # ./  ../  .git/   ← hidden folder
git status    # On branch master · No commits yet · nothing to commit
touch index.html
git status    # Untracked files: index.html (red)
git add index.html
git status    # Changes to be committed: new file: index.html (green)
git commit -m "create index.html"   # [master (root-commit) 8106280]
git status    # nothing to commit, working tree clean
git log       # commit hash, Author, Date, message

Three areas: Working directory → (add) → Staging area → (commit) → Repository. Untracked = red; staged = green. Undo staging: git rm --cached <file> (new file) or git restore --staged <file>. Discard edits: git restore <file>.

The .git folder is hidden (enable Hidden items in File Explorer’s View tab); it holds the entire history. The file you created (index.html) is 0 KB at first. Open it in VS Code, add <h1> hello my file ! </h1>.

6. Modifying a file and committing again

After editing: git status → Changes not staged for commit, modified: index.html (red). Run git add index.html → Changes to be committed (green). Then git commit -m "adding header" (13 insertions).

The commit hash / ID is the long 40-character code after “commit” in git log (e.g. b2cca50d…). Short form = first 7 characters (b2cca50). Each commit has a unique ID.

7. Detached HEAD state 
git checkout b2cca50d2aeb8cdbaa0d404a2478550cf7654077
  • You view the project as it was at that commit.
  • HEAD points to a commit, not a branch like master.
  • Changes aren’t saved to a branch unless you create a new branch or switch back.
  • Useful for testing/exploring without affecting active branches.

git branch shows * (HEAD detached at b2cca50). Create a branch to keep work: git switch -c <name>. Undo: git switch -. Return: git checkout master.

8. Branches & merging 
git branch mybranch        # creates it, but you STAY on master
git checkout mybranch      # now switched
# edit title: Document → myDocument
git add index.html
git commit -m "changing in title"   # [mybranch d0ff64e]
git checkout master
git log                    # "changing in title" is NOT here
git merge mybranch         # Updating b2cca50..d0ff64e  Fast-forward

Right after creating it, mybranch and master point to the same commit (HEAD -> mybranch, master). The new commit lives only on mybranch until merged. Fast-forward = master hasn’t moved, so Git just slides master up to mybranch’s commit (no merge commit). After merge both show on the same commit d0ff64e. The slide title says “Merge updates mybranch with master” – in practice you stand on master and merge mybranch into it.

9. GitHub: remote repository & push/pull
  1. Sign in → + → New repository. Set owner, name (“myproject”), description, Public/Private, optional README, .gitignore, license. Default branch is main. Click Create repository.
  2. Code button → copy the HTTPS clone URL.
git remote -v                                   # empty at first
git remote add origin https://github.com/shereenYehia22/myproject.git
git remote -v                                   # origin … (fetch) / (push)
git push -u origin master                       # browser asks to authorize Git Credential Manager
git pull origin master                          # Already up to date.

push = upload local commits to the remote. pull = fetch + merge remote updates into local branch. origin = default name of the remote. -u (upstream) links local branch to remote branch so later you only type git push / git pull (without it: git push origin master).

Slide observation: GitHub’s default branch is main (README “Initial commit”) but the local branch was master, so pushing created a second branch “master” (“2 Branches”, 3 commits ahead of / 1 behind main). Compare & pull request is offered.

Commits page: shows commits 1 = create index.html (8106280), 2 = adding header (b2cca50), 3 = changing in title (d0ff64e). Opening one shows the diff: red “−” removed line, green “+” added line.

10. Collaborators & Take Care

Add collaborators: repo → 1. Settings → 2. Collaborators → 3. Add people. Without collaborators only you can contribute.

Take Care: every student in the project team must use Git and GitHub, and it has a high mark on the project score. Resources: two YouTube tutorials listed on the slides.

Smart Summary

  • Git = local version control · GitHub = online hosting/collaboration.
  • Repo = project files + full history. Local (device, offline) vs Remote (server). Public (view all) vs Private (permission).
  • Setup: install 64-bit → Git Bash → git config --global user.name / user.email.
  • Flow: init → add → commit → log; check with status.
  • Areas: Working dir → Staging → Repository. Red = untracked/modified; green = staged.
  • .git = hidden folder holding history; seen with ls -a.
  • Commit hash = unique ID; checkout <hash> → detached HEAD (explore only).
  • Branch: git branch x creates; checkout x switches; commits stay on x until merge (fast-forward if master unchanged).
  • GitHub link: remote add origin URL → push -u origin master → pull.
  • Collaborators: Settings → Collaborators → Add people. Team use of Git/GitHub = high project marks.
Mnemonics: “I-A-C-L” = Init, Add, Commit, Log. “Add → Commit → Push” = Stage, Save, Share. Hash = fingerprint. Detached HEAD = visiting the past as a tourist: you can look, but souvenirs (commits) get lost unless you make a branch.

Common mistakes & traps

  • Forgetting git add after editing → commit includes nothing.
  • git branch x does not switch; you need checkout.
  • Commits on a branch don’t appear in master’s log until merged.
  • Public ≠ anyone can edit (only view).
  • Local master vs GitHub main → extra branch on push.
  • Git ≠ GitHub. git init alone doesn’t track files; they start untracked.
  • -u is about upstream tracking, not “update”.
